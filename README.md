# Examination Management and Item Analysis System — Prototype

A simple, local, console-based Python prototype demonstrating:

Excel question bank → exam creation → exam activation → student exam → answer recording → score calculation → exam inactivation → item analysis → JSON → Excel.

The JSON files and exported worksheets are generated by the program and are based on the actual stored examination results.

## Exam activation and inactivation

Examinations are created but remain inactive until the teacher explicitly activates them.

- Creating an examination does not automatically activate it.
- Activating an examination marks it as active and makes it available to students.
- Only one examination can be active at a time.
- Activating another examination automatically deactivates the previous one.
- Inactivating an examination makes it unavailable for student access immediately.
- When no examination is active, the student menu displays:

```text
No examination is currently active.
Please wait for the teacher to activate
an examination.
```

## Item analysis workflow

Item Analysis is performed from actual stored responses in `data/results.json`.

The teacher menu includes:

1. Import Excel Questions
2. View Question Bank
3. Create Examination
4. Activate Examination
5. Inactivate Examination
6. View Active Examination
7. Item Analysis
8. Export Analysis to Excel
9. Return

Inside Item Analysis the teacher can:

1. View Item Analysis
2. View Student Results
3. Sort / Filter Analysis
4. Generate JSON Analysis
5. Return

Sorting and filtering are applied only to the generated analysis data, not to the imported question bank itself.

## How Number Wrong is calculated

For each question, the prototype uses actual stored responses only.

- Total Responses = number of student answers recorded for the question
- Number Correct = count of responses where `is_correct` is `true`
- Number Wrong = Total Responses - Number Correct

This is computed directly from `data/results.json` and never estimated.

## How student scores are calculated

Each student exam result is stored as a set of per-question responses under one `result_id`.

The score for a student is:

`score = number of correct answers`

The percentage is:

`percentage = (score / total_questions) * 100`

These values are read from the saved responses and displayed in the item analysis and export workbook.

## How students who answered incorrectly are identified

For each question, the analysis inspects the recorded responses and keeps the responses where `is_correct` is `false`.

Then it lists:

- Student name
- Student answer
- Student score
- Student percentage

If no student answered the question incorrectly, the prototype displays:

```text
Students who answered incorrectly:
None
```

## Sorting and filtering on analysis data

The sorting/filtering menu in Item Analysis allows the teacher to:

- Sort by Question ID
- Sort by Difficulty Index
- Sort by Discrimination Index
- Filter by Module
- Filter by Question Type
- Show All

This keeps the imported question bank stable while allowing result analysis to be organized after the exam is complete.

## What is included in analysis.json

`output/analysis.json` includes both student-level and item-level analysis data. The structure contains:

- `exam`
- `students`
- `questions`
- `reliability`
- `student_results`
- `items`

Each item entry includes:

- question ID
- question text
- module
- question type
- correct answer
- total responses
- number correct
- number wrong
- difficulty index
- discrimination index
- list of students who answered incorrectly
- recommendation

## Prototype limitations

- This is a console prototype, not a web application.
- Student identity is a name only; there is no login or authentication.
- Data is stored in JSON files instead of a database.
- Image display is limited to file-path output in the console.
- The prototype compares written answers using simple case-insensitive matching.
- Programming responses are compared as stored strings and are not executed.
- Reliability is a prototype statistic and is only meaningful when enough real student data exists.
- All item analysis values come from actual stored examination results only.

```bash
python -m pip install -r requirements.txt
```

```bash
python main.py
```

## Example workflow

1. Import the sample Excel workbook.
2. View the question bank.
3. Create an exam.
4. Activate the exam.
5. Student takes the exam and submits answers.
6. Teacher inactivates the exam.
7. Teacher opens Item Analysis.
8. Review student scores and question-level statistics.
9. Sort or filter analysis data as needed.
10. Generate `analysis.json`.
11. Export the workbook to `item_analysis.xlsx`.

No fake data is generated. All analysis is computed from actual saved results.
